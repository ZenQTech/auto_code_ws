# 验收标准

## 1. 模块级验收

### 1.1 agv_control - CmdMux 模块

**验收条件：**

| 编号 | 验收项 | 验证方法 | 通过标准 |
|------|--------|---------|---------|
| CM-01 | `submit()` 对无效 source 值安全处理 | 单元测试传入 source=99, 255 | 无 crash，无数组越界，静默返回 |
| CM-02 | `set_timeout()` 对无效 source 值安全处理 | 单元测试传入 source=99, 255 | 无 crash，无数组越界，静默返回 |
| CM-03 | `get_effective()` 不使用魔术数字 | 代码审查 | 循环上限使用命名常量 `_COUNT` |
| CM-04 | 并发安全性 | 多线程压力测试 (1000 次 submit) | 无 data race，无 crash |
| CM-05 | force_stop 最高优先级 | 测试：force_stop 后 get_effective() 返回零值 | 零值 Twist，即使有活跃命令 |
| CM-06 | 超时后命令失效 | 提交命令后等待超过 timeout_ms | get_effective() 跳过超时命令 |
| CM-07 | AddressSanitizer 通过 | 编译 -fsanitize=address 运行测试 | 0 个内存错误报告 |
| CM-08 | UndefinedBehaviorSanitizer 通过 | 编译 -fsanitize=undefined 运行测试 | 0 个未定义行为报告 |

**阻塞条件：** CM-01 或 CM-02 失败 → 阻塞所有后续任务

## 5. 验收流程

### 5.1 验收阶段划分

```
Phase 1: 模块级验收
  ├── 1.1 CmdMux 单元测试全部通过
  ├── 1.2 LifecycleManager 单元测试全部通过
  └── 1.3 字符串工具单元测试全部通过
          │
          ▼
Phase 2: 集成验收
  ├── 2.1 全量编译 0 警告 (Werror)
  ├── 2.2 安全编译选项验证
  └── 2.3 ASan/UBSan 联合测试通过
          │
          ▼
Phase 3: 系统级验收
  ├── 3.1 Gazebo 仿真端到端测试
  ├── 3.2 后端系统兼容性测试
  └── 3.3 长时间稳定性测试
          │
          ▼
Phase 4: 安全验收
  ├── 4.1 红线检查清单全部通过
  ├── 4.2 模糊测试无 crash
  └── 4.3 代码审查确认
```

### 5.2 验收通过条件

- **Phase 1-3** 中所有验收项必须通过
- **Phase 4** 中所有红线项（SEC-01 ~ SEC-06）必须通过
- 模糊测试（SEC-07 ~ SEC-09）运行 10 分钟 0 crash
- 代码审查由至少 2 名审查者确认

### 5.3 回归测试要求

- 每次提交必须运行 Phase 1 全部测试
- 每次 PR 合并必须运行 Phase 1 + Phase 2
- 每次发布前必须运行 Phase 1-4 全部测试
