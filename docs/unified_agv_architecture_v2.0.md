## 2. 术语表与命名约定

### 2.1 术语表

| 术语 | 含义 |
|------|------|
| AGV | Automated Guided Vehicle，自动导引车，本系统为差速驱动模型 |
| TOS | Transport Order Scheduler，运输任务调度器 |
| FMS | Fleet Management System，车队管理系统 |
| DDS | Data Distribution Service，数据分发服务（ROS2底层通信中间件） |
| SIL | Safety Integrity Level，安全完整性等级 |
| SLC | Safety Logic Controller，安全逻辑控制器（双通道安全PLC） |
| EKF | Extended Kalman Filter，扩展卡尔曼滤波 |
| AMCL | Adaptive Monte Carlo Localization，自适应蒙特卡洛定位 |
| TEB | Timed Elastic Band，定时弹性带（局部路径规划） |
| DWA | Dynamic Window Approach，动态窗口法（局部路径规划） |
| FCL | Flexible Collision Library，柔性碰撞检测库 |
| ROS2 | Robot Operating System 2 (Humble) |
| Ignition | Gazebo Ignition Fortress (现已更名 Gazebo) |
| SIL2 | Safety Integrity Level 2，按 IEC 61508 标准 |
| PLC | Programmable Logic Controller，可编程逻辑控制器 |
| SBC | Safety Bumper Controller，安全触边控制器 |
| USS | Ultrasonic Sensor，超声波传感器阵列 |

### 2.2 命名约定

| 类别 | 约定格式 | 示例 |
|------|----------|------|
| ROS2 包名 | `agv_<功能>` | `agv_scheduler`, `agv_navigation` |
| ROS2 节点名 | `<位置>_<功能>` | `central_scheduler`, `agv_01_local_planner` |
| Topic 名 | `/<domain>/<agv_id>/<功能>` | `/fleet/task/assign`, `/agv_01/cmd_vel` |
| Service 名 | `/<domain>/<功能>` | `/fleet/scheduler/submit_task` |
| Action 名 | `/<domain>/<agv_id>/<功能>` | `/fleet/scheduler/execute_task` |
| 参数名 | `<模块>.<参数>` | `safety.front_zone_distance` |
| 坐标系 | `map`, `odom`, `base_footprint`, `base_laser`, `base_camera_front`, `base_camera_rear`, `base_ultrasonic` | 遵循 REP 105 |
| AGV 标识 | `agv_01` ~ `agv_05` | 3-5 台 AGV |
| 安全PLC | `safety_plc_<agv_id>` | `safety_plc_agv_01` |

### 2.3 文档标签约定

- **[DEFAULT]** — 当前采用的默认方案
- **[EXTENSION]** — 预留的扩展接口
- **[HARDWARE]** — 硬件直接实现，软件层仅为接口
- **[CRITICAL]** — 安全关键路径组件

**通信说明：**
- 中央控制台与各AGV之间通过 WiFi 5/6 局域网连接，使用 Fast DDS（默认RMW）
- 同一台机器上的节点间通信使用 DDS Shared Memory (SHM) 零拷贝传输
- 安全相关 Topic 使用独立 Partition `safety`，与业务数据隔离
- 每台AGV内部传感器数据使用 localhost DDS，不经过网络

## 4. ROS2 节点清单

### 4.1 中央控制台节点（运行于中央工控机）

| 序号 | 节点名称 | ROS2 包 | 语言 | 职责 | 实时性要求 | 启动优先级 |
|------|----------|---------|------|------|-----------|-----------|
| C-01 | `central_scheduler` | `agv_scheduler` | C++ | 全局任务调度：接收任务、优先级排队、AGV分配、任务生命周期管理 | ≤500ms | 3 |
| C-02 | `traffic_controller` | `agv_traffic_control` | C++ | 交通管制：交叉口资源管理、路径段锁、死锁检测与解锁 | ≤100ms | 3 |
| C-03 | `fleet_state_manager` | `agv_fleet_manager` | C++ | 车队状态管理：AGV注册/注销、状态聚合、健康监控、心跳监测 | 10Hz | 2 |
| C-04 | `map_server` | `agv_map_server` | C++ | 全局地图服务：地图加载/保存、代价地图生成、区域定义 | 按需 | 1 |
| C-05 | `api_gateway` | `agv_api_gateway` | Python | REST API 网关：外部系统对接、请求验证、限流、WebSocket推送 | 非实时 | 4 |
| C-06 | `monitor_aggregator` | `agv_monitor` | C++ | 监控数据聚合：采集全系统指标、告警生成、可视化数据转发 | 5Hz | 3 |
| C-07 | `charge_scheduler` | `agv_scheduler` | C++ | 充电调度：低电量检测、充电站分配、充电任务触发 | 1Hz | 3 |
| C-08 | `central_safety_monitor` | `agv_safety` | C++ | 中央安全监控：全局急停广播、安全门联锁监测、全车队安全状态聚合 | ≤10ms | 2 |

### 4.2 车载端节点（每台AGV各运行一份，共3-5份）

| 序号 | 节点名称 | ROS2 包 | 语言 | 职责 | 实时性要求 | 进程隔离 |
|------|----------|---------|------|------|-----------|---------|
| V-01 | `agv_XX_global_planner` | `agv_navigation` | C++ | 全局路径规划：接收目标位姿，基于全局代价地图搜索最优路径（A*/Hybrid A*），路径平滑 | ≤50ms | 共享进程 |
| V-02 | `agv_XX_local_planner` | `agv_navigation` | C++ | 局部路径规划：跟踪全局路径，TEB/DWA轨迹优化，动态障碍物避障，输出速度指令 | 100Hz (10ms) | 共享进程 |

### 5.3 故障安全策略的软件实现

#### 5.3.1 故障检测矩阵

| 故障类型 | 检测方式 | 检测延迟 | 安全动作 | SIL2 | 恢复方式 |
|----------|---------|---------|---------|------|---------|
| 障碍物侵入安全区 (前<0.8m) | LiDAR + 超声波 | ≤10ms | 急停 (cmd_vel=0) | 是 | 障碍物移除后自动恢复 |
| 障碍物侵入减速区 (前<0.5m) | LiDAR + 超声波 | ≤10ms | 减速至 0.3 m/s | 是 | 障碍物远离后自动恢复 |
| 侧后障碍物 (<0.3m) | 超声波 + LiDAR | ≤10ms | 急停 | 是 | 障碍物移除后自动恢复 |
| 安全触边触发 | 安全PLC GPIO | ≤5ms | 急停 + 电机抱闸 | 是 | 钥匙复位 |
| 急停按钮按下 | 安全PLC GPIO | ≤5ms | 急停 + 电机抱闸 | 是 | 钥匙复位 |
| 控制台总急停 | 中央safety_monitor | ≤10ms | 全车队急停 | 是 | 手动确认 |
| 安全门联锁 | 中央safety_monitor | ≤10ms | 全车队急停 | 是 | 门关闭+手动确认 |
| 通信中断 (>500ms) | 心跳超时检测 | ≤500ms | 急停 (本地安全) | 是 | 通信恢复后 1s 恢复 |
| 定位跳变 (>0.5m/帧) | EKF协方差监测 | ≤10ms | 急停 | 是 | 定位恢复后确认 |
| 超速 (>1.8 m/s = 120%) | 速度反馈监测 | ≤10ms | 急停 | 是 | 速度正常后确认 |

#### 5.3.4 安全代码约束（实时循环内强制）

```
[CRITICAL] safety_controller 与 plc_bridge 节点实时循环 (100Hz) 内：

禁止的操作:
  ❌ 动态内存分配 (new/delete/malloc/free/calloc/realloc)
  ❌ C++ STL 容器动态扩容 (std::vector::push_back 可能触发 realloc)
  ❌ 阻塞操作 (sleep/usleep/nanosleep/mutex_lock/条件变量等待)
  ❌ 文件 I/O (fopen/fread/fwrite/fclose)
  ❌ 高频日志 (实时循环内禁止 spdlog/printf)
  ❌ 异常抛出与捕获 (throw/try/catch)
  ❌ 虚函数调用 (避免 vtable 查找的不确定延迟)
  ❌ 递归函数调用

允许的操作:
  ✅ 栈上分配 (固定大小 POD 数组)
  ✅ 预分配内存池 (启动时一次分配，运行时复用)
  ✅ 原子操作 (std::atomic<bool>/std::atomic<uint32_t>)
  ✅ 无锁队列 (boost::lockfree::spsc_queue 或类似)
  ✅ 固定大小 ring buffer (预分配, O(1) 访问)
  ✅ 位运算与整数运算
  ✅ 简单浮点运算 (不触发异常)
```

## 7. 技术选型建议

### 7.1 SLAM 与定位方案

| 方案 | 适用场景 | 精度 | 实时性 | 推荐度 | 说明 |
|------|---------|------|--------|--------|------|
| **EKF (robot_localization)** | 多传感器融合 | ±5cm (动态) | ≥50Hz | ⭐⭐⭐⭐⭐ **[DEFAULT]** | ROS2标准包，融合LiDAR+IMU+里程计 |
| **AMCL** | 全局重定位 | ±2cm (静态) | 10-30Hz | ⭐⭐⭐⭐ | 定位丢失时恢复 |
| **Cartographer** | 3D SLAM建图 | ±3cm | 20-30Hz | ⭐⭐⭐⭐ | 支持3D LiDAR，建图阶段使用 |
| **RF2O (Range Flow)** | 纯LiDAR里程计 | ±3cm | 100Hz | ⭐⭐⭐ | 计算量小，可作为EKF输入 |

**最终方案：**
- **建图阶段**: Cartographer (3D LiDAR + IMU) → 生成全局地图
- **运行阶段**: EKF (robot_localization) 主定位 + AMCL 重定位备用
- **EKF输入**: 3D LiDAR scan matching (RF2O/ICP) + IMU 预积分 + 轮式里程计
- **定位降级策略**: EKF协方差监测 → 协方差超阈值 → 触发AMCL重定位 → 失败 → 安全急停

### 7.2 全局路径规划算法

| 算法 | 复杂度 | 500m² 场景 | 推荐度 | 说明 |
|------|--------|-----------|--------|------|
| **A\*** | O(N) | < 5ms | ⭐⭐⭐⭐⭐ **[DEFAULT]** | 栅格地图成熟稳定，500m² 计算量极小 |
| **Hybrid A\*** | O(N log N) | < 20ms | ⭐⭐⭐⭐ | 差速模型下生成平滑路径，作为扩展预留 |
| **Theta\*** | O(N) | < 10ms | ⭐⭐⭐ | 路径更短但实现复杂 |
| **Dijkstra** | O(N log N) | < 10ms | ⭐⭐⭐ | 无启发式，不适合实时 |

**[DEFAULT] A\* 算法** (8方向扩展 + 路径平滑后处理)
- 500m² 场景 0.05m 分辨率 → 约 2000x2000 = 4M cells
- A* 搜索范围通常为整个地图的 20-30% → ~1M cells
- 预期计算时间: < 5ms (C++ 实现, 优先队列优化)
- 满足 ≤ 50ms 的要求

### 7.3 局部路径规划与避障算法

| 算法 | 实时性 | 多约束支持 | 推荐度 | 说明 |
|------|--------|-----------|--------|------|
| **TEB** | 50-100Hz | 速度/加速度/障碍物 | ⭐⭐⭐⭐⭐ **[DEFAULT]** | 多约束轨迹优化，适配差速模型 |
| **DWA** | 100Hz+ | 速度空间 | ⭐⭐⭐⭐ | 计算量小，作为扩展预留 |
| **MPC** | 20-50Hz | 模型预测 | ⭐⭐⭐ | Jetson Orin上可行，实现复杂 |

**[DEFAULT] TEB (Timed Elastic Band)**
- 100Hz 控制频率在 Jetson Orin 上可满足
- 支持速度/加速度约束、障碍物避让、路径跟踪
- ROS2 Navigation2 原生支持

**避障策略：**
- TEB 内置避障 (基于 costmap 代价) — 主避障
- VFF (虚拟力场法) — 紧急避障备用 (计算量极小)
- FCL 碰撞检测 — 安全控制器中的碰撞预测

### 7.4 调度算法

| 算法 | 复杂度 | 3-5台AGV | 推荐度 |
|------|--------|---------|--------|
| **改进型拍卖算法** | O(N²) | < 1ms | ⭐⭐⭐⭐⭐ **[DEFAULT]** |
| **贪心匹配** | O(N log N) | < 0.1ms | ⭐⭐⭐⭐ |
| **匈牙利算法** | O(N³) | < 1ms | ⭐⭐⭐⭐ |

**[DEFAULT] 改进型拍卖算法 (优先级感知)**
- 支持优先级抢占: CRITICAL > HIGH > NORMAL > LOW
- 负载均衡: 累积任务时间 + 当前电量 + 位置距离
- 3-5台AGV场景 O(N²) 复杂度完全可忽略

### 7.5 数据库/存储方案

| 用途 | 推荐方案 | 说明 |
|------|---------|------|
| **任务记录** | SQLite / PostgreSQL | 任务日志、历史查询，SQLite足够3-5台AGV规模 |
| **地图文件** | 文件系统 (PGM/YAML) | OccuapncyGrid 格式，文件存储 |
| **配置参数** | YAML 文件 + ROS2 Parameter Server | 运行时动态加载 |
| **运行日志** | ROS2 bag (rosbag2) | 录制/回放传感器数据和控制指令 |
| **系统指标** | Prometheus + Grafana (可选) | 可扩展的监控方案 |
| **安全日志** | 独立文件 + 不可篡改日志 | 安全审计要求 |

**[DEFAULT] 选择：SQLite (轻量级) + rosbag2 (数据录制)**
- 3-5台AGV规模无需分布式数据库
- SQLite 存储任务记录和系统配置
- rosbag2 录制传感器/控制数据用于回放分析

### 7.7 感知方案

## 10. 自定义消息必要性分析

### 10.1 自定义消息清单

| 消息名称 | 必要性 | 替代方案 | 选用理由 |
|----------|--------|---------|----------|
| `SafetyState.msg` | **必需** | 无ROS标准替代 | SIL2安全等级需要独立的安全状态通道，含多层速度限幅信息，非ROS标准消息可覆盖 |
| `EmergencyStatus.msg` | **必需** | 无ROS标准替代 | 需区分15种急停源，含双通道PLC状态，标准消息无法表达 |
| `PLCStatus.msg` | **必需** | 无ROS标准替代 | 双通道安全PLC专有状态(通道一致性、急停按钮x4、触边、超声波、抱闸)，硬件专用 |
| `TaskAssignment.msg` | **必需** | `std_msgs/String` + JSON | 需要类型安全的ROS2消息，含路径、速度限制等多字段 |
| `TaskStatus.msg` | **必需** | `action_msgs/GoalStatus` | GoalStatus不含progress、error_msg等字段 |
| `Heartbeat.msg` | **必需** | `diagnostic_msgs/DiagnosticStatus` | 心跳需要序列号(seq)检测丢包，标准消息不含此字段 |
| `CentralHeartbeat.msg` | **必需** | 同上 | 中央心跳需包含全局急停、安全门、活跃AGV列表等状态 |
| `FleetState.msg` | **必需** | 无ROS标准替代 | 车队级聚合消息，含多台AGV状态数组 |
| `GlobalEStop.msg` | **必需** | `std_msgs/Bool` | 需携带触发源、原因描述等信息 |
| `TaskAssignment.msg` | **必需** | 见上 | 同上 |
| `Navigate.action` | **必需** | `nav2_msgs/action/NavigateToPose` | Nav2标准Action可复用，推荐直接使用 |
| `Charge.action` | **必需** | 无标准替代 | 充电任务含电池前后电量、充电状态等专有字段 |
| `ExecuteTask.action` | **必需** | 无标准替代 | 外部系统任务提交通用接口 |

### 10.2 可直接复用的ROS2标准消息

| 场景 | 消息类型 | 说明 |
|------|---------|------|
| 速度指令 | `geometry_msgs/msg/Twist` | 标准速度指令 |
| 位姿 | `nav_msgs/msg/Odometry` | 含协方差的位姿，适合EKF融合 |
| 激光雷达 | `sensor_msgs/msg/LaserScan` | 2D激光扫描 |
| 3D点云 | `sensor_msgs/msg/PointCloud2` | 3D LiDAR点云 |
| 图像 | `sensor_msgs/msg/Image` | RGB-D相机图像 |
| 深度图像 | `sensor_msgs/msg/Image` | 深度图 |
| IMU | `sensor_msgs/msg/Imu` | IMU标准消息 |
| 超声波 | `sensor_msgs/msg/Range` | 单束超声波距离 |
| 电池 | `sensor_msgs/msg/BatteryState` | 电池状态 |
| 路径 | `nav_msgs/msg/Path` | 路径标准消息 |
| 地图 | `nav_msgs/msg/OccupancyGrid` | 占用栅格地图 |
| 导航Action | `nav2_msgs/action/NavigateToPose` | Nav2标准导航Action (推荐直接复用) |
| TF | `tf2_msgs/msg/TFMessage` | 坐标变换 |

### 10.3 自定义消息 vs 复用标准消息的策略矩阵

| 决策 | 条件 | 示例 |
|------|------|------|
| **复用标准消息** | ROS2生态已有成熟消息，且字段完全覆盖需求 | cmd_vel → Twist, scan → LaserScan, pose → Odometry |
| **复用标准Action** | Nav2等标准包已提供，直接使用 | navigate → NavigateToPose |
| **扩展标准消息** | 标准消息大部分适用但缺少数个字段 | 不推荐，ROS2消息无法继承。改用自定义消息+标准消息组合 |
| **自定义消息** | 业务语义独特，无标准消息覆盖 | SafetyState, PLCStatus, TaskAssignment |

## 11. 验收标准覆盖矩阵

| 验收项 | 验收阶段 | 涉及模块 | 关键接口 | 架构保障措施 |
|--------|---------|----------|----------|-------------|
| AC-1 无碰撞运行 | 全阶段 | 全部 | `/agv_XX/scan`, `/agv_XX/obstacle_map`, `/fleet/traffic/*` | 双重避障(感知+安全) + 交通管制 + 三层速度限幅 |
| AC-2 急停响应 ≤ 10ms | 全阶段 | safety_controller, plc_bridge | `/agv_XX/emergency`, `/agv_XX/plc_status` | 安全进程独立CPU核心 + SCHED_FIFO + 禁止动态内存 |
| AC-3 定位精度 ≤ 5cm | P1/P3 | localization | `/agv_XX/pose` | EKF多传感器融合 + AMCL重定位备用 + 降级策略 |
| AC-4 避障响应 ≤ 50ms | P1/P3 | local_planner, safety_controller | `/agv_XX/cmd_vel` | TEB 100Hz控制循环 + 安全控制器独立100Hz检测 |
| AC-5 调度响应 ≤ 500ms | P2/P3 | central_scheduler | `/fleet/scheduler/submit_task` | 拍卖算法O(N²)在3-5台规模下 < 1ms |
| AC-6 定位 ≥ 20Hz | P1/P3 | localization | `/agv_XX/pose` | EKF ≥ 50Hz输出，远超20Hz要求 |
| AC-7 控制回路 100Hz | P1/P3 | local_planner, controller, safety_controller | `/agv_XX/cmd_vel` | 所有控制节点100Hz定时器循环 |
| AC-8 任务完成率 ≥ 90% (50场景) | P1 | 全部 | 全部 | 系统级端到端验证 |
| AC-9 SIL2安全通道完整 | P2/P3 | safety_controller, plc_bridge | `/agv_XX/plc_status`, `/agv_XX/emergency` | 双通道PLC + 双路软件急停 + 四层安全防御 |
| AC-10 安全区域(前0.8m/侧后0.3m) | P2/P3 | safety_controller, plc_bridge | `/agv_XX/ultrasonic`, `/agv_XX/scan` | LiDAR + 超声波双路径检测 |
| AC-11 减速区(0.5m) | P2/P3 | safety_controller | `/agv_XX/safety_state` | Level 2速度限幅独立检测 |
| AC-12 通信中断恢复 | P2/P3 | lifecycle, fleet_state_manager | `/agv_XX/heartbeat`, `/fleet/central_heartbeat` | 500ms超时本地急停 + 恢复后1s正常 |
| AC-13 急停按钮(4个/AGV) | P2/P3 | plc_bridge, 安全PLC | `/agv_XX/plc_status` | 安全PLC GPIO直接读取，硬件级响应 |
| AC-14 控制台总急停 | P2/P3 | central_safety_monitor | `/fleet/global_estop` | 中央安全监控发布全车队急停广播 |
| AC-15 安全门联锁 | P2/P3 | central_safety_monitor | `/fleet/global_estop` | 门状态监测 + 全车队急停 |
| AC-16 急停钥匙复位 | P2/P3 | plc_bridge, 安全PLC | `/agv_XX/emergency_release` | 安全PLC硬件确认复位 → 软件确认 |
