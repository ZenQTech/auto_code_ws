# 需求文档：多 AGV 智能调度平台

## 1. 功能需求

### 1.1 单 AGV 核心功能（7 大模块）
1. **SLAM 建图与定位模块**：基于 SICK TiM561 单线 LiDAR（270° FOV, Ethernet）+ RealSense D435 深度相机 + 轮式里程计 + IMU，实现实时建图与 ±5cm 精度定位
2. **路径规划模块**：全局路径规划（A*/Dijkstra）+ 局部动态避障（DWA/TEB），支持动态障碍物规避
3. **运动控制模块**：差分驱动底盘控制，接收速度指令并执行闭环控制（PID/MPC），输出 PWM/ CAN 指令
4. **感知与避障模块**：融合 LiDAR + 深度相机数据，实现多层级安全区域检测（警告区/减速区/急停区）
5. **任务调度模块**：接收 WMS 任务指令，解析为 AGV 可执行的动作序列，管理任务队列与优先级
6. **状态监控模块**：实时上报 AGV 位置、速度、电量、任务状态、故障信息至 WMS
7. **通信模块**：基于 ROS2 话题/服务/动作实现模块间通信，通过 REST API 与 WMS 对接

### 1.2 多 AGV 协同调度
- 支持 N 台 AGV 同时运行，含分布式死锁检测与自动化解机制
- 动态路径重规划：当多车路径冲突时，自动调整优先级与绕行路线
- 交通流优化：基于全局地图的车流密度分析与路径负载均衡
- 交通管制：交叉路口/窄道等关键区域的通行权仲裁

### 1.3 WMS 对接
- WMS 为已有外部系统，我方提供标准 REST API 接口规范
- 接口功能：任务下发、任务状态查询、AGV 状态上报、地图数据查询、异常告警推送
- 通信协议：HTTPS + JSON，支持 API Key 认证

### 1.4 操作模式
- 自动导航模式：全自主执行 WMS 下发的运输任务
- 手动控制模式：通过手柄/键盘手动操控，用于调试与异常恢复
- 模式切换：纯软件切换 + ROS2 生命周期节点管理状态转换，急停为独立硬件通道

## 2. 非功能需求

- **性能**：
  - 控制回路周期 ≤ 50ms（20Hz 最低控制频率）
  - 感知处理延迟 ≤ 100ms（LiDAR 点云 + 相机图像融合）
  - 路径规划响应时间 ≤ 200ms（全局重规划）
  - 多 AGV 死锁检测周期 ≤ 500ms
- **安全**：
  - 满足 SIL-2（IEC 61508）安全完整性等级
  - 急停响应时间 ≤ 100ms（从触发到电机断电）
  - 安全区域三级防护（警告区/减速区/急停区）
- **定位**：
  - 静态定位精度 ±3cm，动态定位精度 ±5cm
  - 定位丢失后恢复时间 ≤ 5s（重定位）
- **可靠性**：
  - 系统可用性 ≥ 99.9%（月度统计）
  - 单 AGV 平均无故障运行时间（MTBF）≥ 500 小时
- **ROS2 规范**：
  - 所有节点遵循 ROS2 生命周期节点（Lifecycle Node）规范
  - 话题/服务/动作命名遵循 ROS2 命名约定（snake_case，命名空间隔离）
  - 使用 QoS 策略：传感器数据用 Best Effort + Keep Last，控制指令用 Reliable + Keep Last

## 3. 约束条件

- **硬件**：
  - 计算平台：Intel NUC（推荐 i7-12 代及以上，16GB+ RAM，512GB+ SSD）
  - 传感器：SICK TiM561 单线 LiDAR（270° FOV, 0.33° 角分辨率, Ethernet）+ Intel RealSense D435 深度相机 + 轮式编码器里程计 + 板载 IMU（9 轴）
  - 底盘：差分驱动底盘（两轮独立驱动 + 万向从动轮）
  - 通信：WiFi 模块（至少支持 802.11ac）
- **软件**：
  - 操作系统：Ubuntu 22.04 LTS
  - ROS2 发行版：ROS2 Humble Hawksbill
  - 仿真平台：Gazebo Ignition Fortress
  - 依赖库：Nav2、ros2_control、slam_toolbox、BehaviorTree.CPP
  - 编程语言：C++17（核心算法与实时节点）、Python 3.10（工具脚本与配置）
- **接口**：
  - WMS 对接：REST API（HTTPS + JSON + API Key 认证）
  - LiDAR 接口：Ethernet（UDP 数据流）
  - 电机控制：CAN bus 或 EtherCAT

## 4. 环境要求

- **运行环境**：
  - 部署场景：室内工业仓库/工厂车间（平整硬质地面）
  - 工作温度：0°C ~ 45°C
  - 工作湿度：10% ~ 90%（无凝露）
  - 光照条件：100 ~ 10000 lux
- **仿真环境**：
  - Gazebo Ignition Fortress
  - 仿真模型需包含：仓库地图（含货架/通道/充电站）、AGV URDF/Xacro 模型、传感器插件（LiDAR/Camera/IMU）
- **网络环境**：
  - WiFi 全覆盖仓库区域，信号强度 ≥ -67 dBm
  - 网络延迟 ≤ 30ms（AGV ↔ 中央调度服务器）

## 5. 安全红线

### 5.1 急停机制
- **硬件急停**：独立硬件通道，物理按钮触发 → 直接切断电机电源（不经过软件），响应时间 ≤ 100ms
- **软件急停**：ROS2 安全守护节点监听系统状态，异常时通过 CAN/EtherCAT 发送电机停机指令
- **双重保护**：硬件急停和软件急停互为冗余，任一触发即停车

### 5.2 速度限制（三层限幅）
- 硬件层：电机驱动器最大速度硬限幅（不可通过软件修改）
- 固件层：嵌入式控制器速度指令限幅
- 软件层：ROS2 控制节点速度指令限幅

### 5.3 安全区域（三级防护）
- 警告区（2m ~ 3m）：减速至额定速度的 50%，发出视觉/声音警告
- 减速区（0.5m ~ 2m）：减速至 0.3 m/s 以下
- 急停区（0 ~ 0.5m）：立即急停

### 5.4 模式切换安全联锁
- 自动 → 手动：需确认 AGV 处于静止状态，通过生命周期节点管理状态转换
- 手动 → 自动：需确认安全区域无障碍、定位状态正常、系统自检通过
- 任何模式下急停按钮始终有效

### 5.5 分级故障处理
| 故障级别 | 故障类型 | 处理策略 |
|---------|---------|---------|
| 轻微 | 传感器短暂异常（< 2s）、WiFi 信号波动 | 降速至 0.5 m/s 运行，上报告警，自动恢复后恢复正常速度 |
| 中等 | LiDAR 遮挡 > 2s、定位置信度下降 | 减速至 0.2 m/s，尝试重定位，30s 内未恢复则停车 |
| 严重 | 定位丢失、WiFi 断连 > 10s、碰撞检测触发、电机故障 | 立即安全停车，锁定任务，等待人工介入恢复 |

### 5.6 安全代码约束
- 所有安全相关节点使用 C++ 实现（避免 Python 的 GC 不确定性）
- 安全关键路径代码禁止动态内存分配（使用栈分配或预分配内存池）
- 安全节点之间使用 Reliable QoS + 心跳机制检测节点存活

| # | 验收项 | 量化标准 | 测试方法 |
|---|-------|---------|---------|
| 1 | 定位精度 | 静态 ±3cm，动态 ±5cm（置信度 95%） | 在仿真环境中设置已知坐标点，记录定位输出与真值偏差 |
| 2 | 避障成功率 | 静态障碍物 ≥ 99%，动态障碍物（1m/s 横穿）≥ 95% | 仿真中随机放置/移动障碍物，统计 1000 次测试的成功率 |
| 3 | 控制周期 | 控制指令发布周期 ≤ 50ms（标准差 ≤ 5ms） | ros2 topic hz 统计 10 分钟运行数据 |
| 4 | 急停响应 | 硬件急停 ≤ 100ms，软件急停 ≤ 200ms | 仿真中注入急停信号，测量从触发到速度归零的时间 |
| 5 | 任务完成率 | 单 AGV 任务完成率 ≥ 99.5%，多 AGV（≥3 台）≥ 98% | 仿真中运行 500 个运输任务，统计完成率 |
| 6 | 死锁化解 | 多 AGV 死锁检测 ≤ 500ms，化解 ≤ 5s | 仿真中制造 4 台 AGV 十字路口冲突场景，测量化解时间 |
